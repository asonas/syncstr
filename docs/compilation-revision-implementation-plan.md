# Compilation membership and artwork implementation plan

Status: proposed implementation plan for the [agreed revised policy](compilation-policy-review.md), recorded in `fa65cfb`. No application behavior is changed by this plan. Cluster prerequisites and delivery gates refer to the [cluster implementation plan](cluster-implementation-plan.md); passing a single-peer test does not establish cluster support.

Implementation progress: stage A is implemented; see [membership repair verification](validation/compilation-membership-repair.md) for its contract and checks. Stage B is implemented locally; see [artwork verification](validation/compilation-artwork.md) for checks and remaining visual/distribution limits. Stage C is implemented locally; see [cluster integration verification](validation/compilation-cluster.md) for automated integration gates and remaining physical-device/distribution limits.

## Outcome and scope

A compilation with a shared source directory and album title, positive compilation evidence, and no external release ID appears as one album with actual participating artist credits. Existing automatically split catalogs are repaired without replacing track identities or overriding listener choices. Missing embedded artwork can be supplemented from album-folder images or the exact corresponding Music library item, retained independently of the audio, and displayed offline after transfer.

Implement the agreed multi-disc rules, artwork selection and refresh, and reversible manual selection. Preserve source files. Keep ambiguous membership and incompatible choices reviewable. External catalog lookup, source-tag rewriting, fuzzy audio matching, and a new Music library importer are outside this work: Music access supplements files already selected for import.

## A: Membership evidence, inference, and migration

1. Define a portable import context that identifies the source grouping scope and directory relationships without transmitting personal absolute paths. Keep context stable across rescans and moves of identified tracks. Equal relative names in unrelated imports do not identify the same source. Preserve track/disc values and the imported assertions used for each assignment.
2. Implement one explicit rule order: protect manual membership and separate-album decisions; reject incompatible release evidence; apply supported release-ID reconciliation; apply same-directory compilation grouping; apply compatible sibling-disc grouping; retain ordinary concrete-credit grouping; otherwise retain/propose provisional groups. Missing, false, uninterpretable, and contradictory assertions remain distinct. Inspect all candidate members before committing a merge so scan order cannot hide a late contradiction.
3. Multi-disc grouping requires the agreed parent boundary, title, consistent positive disc numbers, no overlap across directories, and compatible credits or positive compilation evidence. A later disc can join the existing album. Unavailable tracks' retained evidence participates in conflict checks; temporary file absence must not erase a separation.
4. Reuse stable album IDs and former-ID references when merging existing provisional groups. Automatic inference must not create a manual membership override. Keep the evidence for undo/reassessment and preserve existing explicit classification choices. If joining would discard incompatible choices, retain the candidates for resolution.
5. Migrate legacy entries transactionally. Use retained metadata/context first; reread original sources only where required and available. Do not synthesize missing directory context from an object store. Missing evidence leaves the old organization usable. Repeated startup/rescan must not allocate new albums or repeat a previously rejected proposal.
6. Apply organization updates through the existing catalog-save path, preserving current track, queue order, selection references, and playback. Refresh legacy metadata from the actual import source without requiring deletion/reimport or changed file digests.

Gate: fictional equivalents of the twenty-track compilation group correctly on fresh import and upgrade; incomplete positive evidence works; conflicting flags/editions/manual separations do not auto-merge; later discs retain album identity; shuffled scan order gives equivalent grouping; repeated scan, restart, move, absence, and migration failure preserve user data. Test Swift and Rust against common expected fixtures rather than separately generated expectations.

## B: Artwork acquisition, persistence, and native transfer

1. Add album artwork candidates with source type, source context, image identity, and their associated track/album references. Preserve imported track artwork separately from the effective album cover. Manual selection and clearing use the existing causal-choice semantics, with image content retained while referenced by a live choice or unresolved conflict.
2. Store normalized image bytes as verified assets separately from audio. Preserve schema-2 artwork on migration; do not classify old bytes as embedded without evidence of their source. Commit references only when the associated image is safely available, or explicitly represent pending acquisition while retaining the last usable cover. Finalize migration/version details jointly with cluster persistence to avoid conflicting version allocations.
3. Acquire sources in the agreed order: manual, embedded, recognized folder image, Music library. Propose `cover.jpg`, `cover.jpeg`, `cover.png`, `folder.jpg`, `folder.jpeg`, and `folder.png`, matched case-insensitively in that fixed order within the album directory; do not scan arbitrary parent directories for images. For disc folders, a shared-parent image is eligible only after that parent is established as the accepted multi-disc scope. Validate formats, dimensions, and byte limits; corrupt images must not fail audio import.
4. Use the current 400-pixel thumbnail policy and 512 KiB transferred-image bound initially; do not upscale a smaller Music image. Keep decoding bounded before normalization. For equivalent-priority track candidates use disc/track order, then a stable identity for ties. Implement replacement only with sufficient provenance/causal evidence; independent incompatible updates remain reviewable rather than using device clocks.
5. On macOS, enumerate the public iTunesLibrary snapshot once per import/refresh operation and index by exact source file location. Read `ITLibMediaItem.artwork.imageData` from the matching item; `artworkForMediaFile` alone does not cover Music-only artwork. Use the original source URL before staging a copy. No title-only matches and no network catalog lookup. Ambiguous library matches are not silently resolved to an arbitrary item.
6. Add `NSAppleMusicUsageDescription` and the necessary read-only Music entitlement in the macOS target. Keep iOS independent of the framework. Verify access granted, denied, and unavailable. Folder import remains usable and retained images survive acquisition errors. Do not request Apple Events access for the iTunesLibrary implementation.
7. Add native album-image preview, manual file/photo selection, clearing back to automatic choice, and conflict resolution. Follow [DESIGN.md](../DESIGN.md). Cancel writes nothing; save persists and refreshes display without audio interruption. Image controls must be reachable on both macOS and iOS; automatic grouping should not require opening the organization sheet.
8. Extend the active transfer contract on Swift and Rust together. Transfer image references, provenance, causal choices, and bounded verified image payloads even when audio is already downloaded. Reject unsupported writer capabilities rather than losing choices. Duplicate/reordered delivery, restart, and partial transfer retain the last valid cover; an image receipt and an audio receipt are separate facts.

Gate: real MP3/M4A/FLAC fixture imports, folder-image fallback, and a signed Music fixture prove acquisition. Native catalog restart and a real Swift/Rust transfer preserve image bytes, priority, selection/clear, and conflicts without retransferring unchanged audio. Native screens prove cancel/save and offline presentation. Run production macOS sandbox verification and iOS build/tests; record TestFlight proof separately. Personal music may be used read-only for an optional smoke check but must not enter published fixtures.

## C: Integration with the shared cluster library

This stage depends on cluster M1 persistence, M2 authorized reconciliation/replication, and M3 merged Apple catalog/source selection. Do not build a competing cluster protocol inside the artwork feature. Stages A and B can deliver local and existing-peer behavior first, provided the retained records do not encode a single Mac as permanent authority.

- Associate import context, album references, image assets, and changes with the cluster's identities and authenticated change model. A replica match uses complete-file content identity; different encodings or tag-modified files remain distinct.
- Recover missing embedded metadata from any reachable verified replica, retaining original grouping context independently of its new path. Prefer metadata exchange when sufficient; audio transfers follow the agreed cellular policy.
- Resolve image priority across the shared candidates. Music availability on one Mac is an acquisition capability, not ownership of the album. An incoming higher-priority automatic candidate can update a shared automatic cover; incompatible manual choices warn and await a shared resolution.
- Retain image assets on library hosts and the images required for playback-device catalog presentation, independently of local audio selection. Preserve availability and confirmed storage separately; missing files or disconnected hosts are not deletions. Connect explicit deletions to cluster tombstones so old image/organization state cannot resurrect deleted library items.

Gate: two headless hosts and native playback clients show one album, replicate its image, and retrieve needed evidence while the original importer or one host is offline. Exercise conflicting manual covers, resolution propagation, missed/reordered changes, duplicate replicas, deletion/re-addition, full offline presentation, and recovery without an original absolute path. Until this gate passes, report cluster behavior as incomplete even if the local compilation and artwork symptoms are fixed.
